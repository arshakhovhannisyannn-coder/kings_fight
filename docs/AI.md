# Ինտելեկտուալ հակառակորդը (AI)

Այս փաստաթուղթը բացատրում է «Արքաների Մարտ» խաղի AI-ի ալգորիթմները։ Կոդը գտնվում է `src/ai/` պանակում և կախված չէ ո՛չ DOM-ից, ո՛չ Electron-ից. նույն կոդն աշխատում է խաղի մեջ (Web Worker-ում) և Node.js-ում (ինքնախաղի և փորձերի համար)։

| Ֆայլ | Դերը |
| --- | --- |
| `evaluate.js` | Գնահատման ֆունկցիա (միավոր + ըստ հատկանիշների բացվածք) |
| `movegen.js` | Թեկնածու քայլերի գեներացիա |
| `view.js` | Ինչ տեղեկություն է հասանելի AI-ին (թաքնված ինֆորմացիա) |
| `easy.js` | «Հեշտ» մակարդակ՝ կանոնների վրա հիմնված |
| `minimax.js` | «Միջին» մակարդակ՝ Minimax + Alpha-Beta |
| `mcts.js` | «Դժվար» մակարդակ՝ Monte Carlo Tree Search |
| `explain.js` | Հայերեն բացատրության գեներացիա |
| `worker.js` | Web Worker-ի պատյան, որպեսզի ինտերֆեյսը չսառի |
| `index.js` | Ընդհանուր մուտքի կետ՝ `chooseMove(state, side, level, opts)` |

## 1. Արդարություն և թաքնված ինֆորմացիա

AI-ը խաղում է **ճիշտ նույն կանոններով**, ինչ խաղացողը՝ նույն եկամուտը, քայլում առավելագույնը 3 քարտ, նույն ժամաչափը (AI-ի մտածելու ժամանակը երբեք չի գերազանցում քայլի ժամաչափի 80%-ը)։

AI-ը **չի տեսնում** խաղացողի ձեռքը և կապուկի հերթականությունը։ Նա գիտի միայն հրապարակային տեղեկությունը.

- խաղացողի 8 քարտանոց կապուկի **կազմը** (ոչ հերթականությունը),
- խաղացողի վերջին խաղացած քարտերը։ Քանի որ խաղացված քարտը գնում է 4 քարտանոց հերթի վերջ, վերջին 4 խաղացված քարտերը հաստատ ձեռքում **չեն**։

Սա իրականացված է `view.js`-ում. `makeView(state, side)` ֆունկցիան պատճենում է վիճակը և հակառակորդի իրական ձեռքը փոխարինում «վիրտուալ ձեռքով»։ Բոլոր ալգորիթմներն աշխատում են միայն այդ պատճենի հետ։ Թեստերից մեկը ստուգում է, որ խաղացողի թաքնված ձեռքի փոփոխությունը չի փոխում AI-ի որոշումը։

AI-ի ողջ պատահականությունն անցնում է սերմով (seed) գեներատորի միջով (mulberry32), ուստի նույն սերմը և նույն բյուջեն տալիս են նույն խաղը։

## 2. Խաղի ծառը և ռաունդի մոդելը

### 2.1. Միաժամանակյա պլանավորումը որպես հաջորդական մոդել

v1.1-ից սկսած ռաունդը բաղկացած է **միաժամանակյա պլանավորումից** (երկու կողմը դնում են մինչև 3 քարտ՝ չտեսնելով իրար քարտերը) և **մարտից** (`battleTicks` = 3 պահ, որոնցում գործում են երկու կողմի զորքերը)։ Միաժամանակյա քայլերով խաղի ճշգրիտ լուծումը խառը ռազմավարություններ է պահանջում, ինչը Minimax-ի և MCTS-ի դասական տարբերակների համար հարմար չէ։ Ուստի շարժիչը պլանավորումը ներկայացնում է **հաջորդական** ձևով.

1. `firstSide` կողմը պլանավորում է առաջինը,
2. `endTurn()`-ը պլանավորումը փոխանցում է մյուս կողմին,
3. երկրորդ `endTurn()`-ը գործարկում է մարտը, ստուգում հաղթանակը և սկսում հաջորդ ռաունդը։

Ծառի մեկ կողը **մեկ կողմի ամբողջ պլանն** է՝ 0–3 տեղադրումների ցուցակ `(քարտ, վանդակ)`։ Ծառի մակարդակները հերթափոխվում են. AI-ի պլան → հակառակորդի պլան → **մարտ** → AI-ի պլան …

### 2.2. AI-ը միշտ առաջին պլանավորողն է

AI-ը որոշում է **ռաունդի սկզբի դիրքից**, երբ հակառակորդի այս ռաունդի ոչ մի քարտ դեռ դաշտում չէ (`chooseMove`-ը անհրաժեշտության դեպքում կանչում է `asFirstPlanner(state, side)`)։ Որոնման մեջ հակառակորդը «պատասխանում է» AI-ի արդեն դրված քարտերին, այսինքն՝ AI-ը ենթադրում է, որ հակառակորդը **տեսնում է** նրա պլանը և ընտրում լավագույն պատասխանը։ Իրականում հակառակորդը այդ քարտերը չի տեսնում, ուստի սա **պեսիմիստական (անվտանգ) ենթադրություն** է. եթե որոնումը լրիվ լիներ, AI-ի ընտրած պլանի իրական արդյունքը չէր կարող ավելի վատ լինել, քան հաշվարկվածը (հաջորդական խաղի minimax արժեքը միաժամանակյա խաղի արժեքի ստորին սահմանն է). գործնականում որոնումը սահմանափակ է խորությամբ և թեկնածուների թվով, ուստի սա մոտավոր երաշխիք է։ Գինը՝ AI-ը երբեմն չափից զգույշ է։

Հավելվածում `firstSide = 1` (AI)։ Ինքնախաղում (`tools/selfplay.js`) երկու AI-ն էլ որոշում են նույն ռաունդի սկզբի դիրքից, հետո քարտերը կիրառվում են շարժիչի հերթականությամբ։

### 2.3. Առաջին պլանավորողի թեկնածուների գնահատումը՝ `settle()`

Առաջին պլանավորողի պլանից հետո մարտը դեռ չի կայացել, և դիրքի ստատիկ գնահատականը քիչ բան կասեր (նոր զորքերը դեռ չեն շարժվել)։ Ուստի `settle()` ֆունկցիան (`src/ai/movegen.js`) թեկնածուն գնահատում է **«զրոյական քայլի»** (null move) միջոցով. հակառակորդը բաց է թողնում իր պլանավորումը, մարտը կատարվում է, և գնահատվում է ստացված դիրքը։ Այս գնահատականով են դասավորվում և կտրվում (beam) թեկնածուները, և դրանով է հաշվվում բացատրության «քայլի ազդեցությունը»։ Երկրորդ պլանավորողի պլանից հետո մարտն արդեն կատարված է, և դիրքը գնահատվում է ուղղակի։

### 2.4. Թաքնված ձեռքը

Հակառակորդի ձեռքը AI-ին հայտնի չէ (տե՛ս բաժին 1)։ Minimax-ը օգտագործում է «վիրտուալ ձեռք»՝ բոլոր քարտերը, որոնք կարող են ձեռքում լինել (դարձյալ պեսիմիստական)։ MCTS-ը կիրառում է **դետերմինիզացիա**. յուրաքանչյուր իտերացիայի սկզբում հակառակորդի անհայտ քարտերը պատահականորեն բաժանվում են ձեռքի և հերթի միջև (`sampleOpponent`), և այդ իտերացիան խաղարկվում է այնպես, կարծես այդ բաշխումը ճիշտ լիներ։ Հազարավոր իտերացիաների միջինը մոտարկում է սպասվող արդյունքը բոլոր հնարավոր ձեռքերի վրա, ուստի MCTS-ը ո՛չ «գուշակում» է ձեռքը, ո՛չ էլ ենթադրում ամենավատը։

Բոլոր հնարավոր պլանների թիվը շատ մեծ է (4 քարտ × մինչև 21 վանդակ 7×9 դաշտում (v1.2-ում՝ 10, v1.3-ում՝ 36) × 3 տեղադրում), ուստի անհրաժեշտ է խելացի գեներացիա։

## 3. Թեկնածու քայլերի գեներացիա (`movegen.js`)

1. **Միայն մատչելի քարտեր** (ոսկին բավարարում է)։
2. **Միայն «օգտակար» վանդակներ**. կամուրջների դիմացի վանդակները, սպառնալիքի տակ գտնվող սեփական աշտարակների կից վանդակները, մեր կիսադաշտ մտած թշնամի զորքերի մոտակա վանդակները։ Հմայքների համար՝ միայն այն թիրախները, որոնք իրոք ինչ-որ բան են անում (օր.՝ «Վահագնի կրակը» պետք է դիպչի առնվազն մեկ թշնամու)։
3. **Հերթականությունը կարևոր չէ.** նույն տեղադրումների տարբեր հերթականությունները համարվում են մեկ քայլ (կրկնությունները հեռացվում են)։
4. **Ճառագայթային որոնում (beam search).** նախ սիմուլացվում են բոլոր մեկ քարտանոց քայլերը, դրանք դասավորվում են ըստ արդյունքի, և միայն լավագույնների հիման վրա են կառուցվում 2 և 3 քարտանոց քայլերը (լայնությունները՝ `beamRoot: [12, 6, 3]` արմատի համար, `beamInner: [6, 3, 2]` ներքին հանգույցների համար)։
5. Յուրաքանչյուր թեկնածու **սիմուլացվում է ամբողջությամբ** (տեղադրում + քայլի կատարում) և գնահատվում է գնահատման ֆունկցիայով։ Ցուցակը վերադարձվում է դասավորված՝ լավագույնը առաջինը։ Այս «արագ գնահատականը» միաժամանակ ծառայում է որպես քայլերի դասավորություն Alpha-Beta-ի համար և որպես տերևների գնահատական։

Շարժիչը շատ արագ է (մեկ քայլի պատճենում + կատարում ≈ 1.5 միկրովայրկյան), ուստի հազարավոր սիմուլյացիաները տևում են միլիվայրկյաններ։

## 4. Գնահատման ֆունկցիա (`evaluate.js`)

Միավորը հաշվվում է AI-ի տեսանկյունից.

```
score = 5   × (Արքայի ամրոցների կյանքի տարբերություն)
      + 3   × (փոքր աշտարակների կյանքի տարբերություն)
      + 2   × (դաշտում զորքի արժեքի տարբերություն. Σ գին × ընթացիկ կյանք / առավելագույն կյանք)
      + 1.5 × (գետն անցած սեփական զորքեր − գետն անցած թշնամի զորքեր)
      + 0.5 × (ոսկու տարբերություն)
      − 2   × (թշնամի զորքեր՝ սեփական աշտարակներից 2 վանդակ հեռավորության վրա)
Արքայի ամրոցն ավերված է → ±∞
```

Կշիռները գտնվում են `config.js`-ի `evalWeights` դաշտում, և 5-րդ փորձը համեմատում է կշիռների տարբեր հավաքածուներ։ `evaluate()` ֆունկցիան վերադարձնում է ոչ միայն միավորը, այլև **յուրաքանչյուր հատկանիշի ներդրումը**, ինչը օգտագործվում է բացատրության համար։

## 5. «Հեշտ» մակարդակ (`easy.js`)

Առանց առաջ նայելու, առաջնահերթության կանոններով.

1. Եթե թշնամի զորքը մոտեցել է սեփական աշտարակին (≤ 3 վանդակ)՝ դնել ամենաուժեղ մատչելի պաշտպանին նրա կողքին։
2. Եթե մատչելի է հերոս / լեգենդար քարտ՝ դնել այն կամրջի դիմաց։
3. Հակառակ դեպքում՝ ամենաէժան զորքը պատահական կամրջի դիմաց։
4. Եթե զորք խաղալ հնարավոր չէ՝ օգտակար հմայք կամ կառույց։

`easyRandomness = 0.3` հավանականությամբ կանոնի փոխարեն ընտրվում է պատահական օրինական քայլ։ Քայլում խաղում է առավելագույնը `easyMaxCards = 2` քարտ։

## 6. «Միջին» մակարդակ. Minimax + Alpha-Beta (`minimax.js`)

**Minimax.** AI-ը ենթադրում է, որ ինքն ընտրում է իր համար առավելագույն գնահատականով քայլը (MAX), իսկ հակառակորդը՝ AI-ի համար նվազագույնը (MIN)։ Ծառը հետազոտվում է մինչև տրված խորությունը, տերևները գնահատվում են գնահատման ֆունկցիայով, և արժեքները «բարձրանում» են դեպի արմատ։

**Alpha-Beta հատում.** α-ն MAX-ի արդեն երաշխավորված լավագույն արժեքն է, β-ն՝ MIN-ինը։ Եթե որևէ հանգույցում α ≥ β, մնացած ճյուղերն այլևս չեն կարող ազդել արդյունքի վրա և չեն հետազոտվում։ Հատումն առավել արդյունավետ է, երբ լավ քայլերը դիտարկվում են առաջինը, ուստի քայլերը նախապես դասավորվում են արագ գնահատականով։

**Իրականացման մանրամասներ.**

- Մեկ «կիսաքայլը» (ply) կողմի ամբողջական քայլն է։
- **Իտերատիվ խորացում.** նախ խորություն 1, հետո 2 (միշտ ավարտվում է), հետո 3՝ եթե ժամանակը բավարարում է (`minimaxDepth: 2`, `minimaxMaxDepth: 3`)։ Նախորդ խորության արդյունքը դասավորում է հաջորդի քայլերը։ Գործնականում խորություն 3-ը տևում է ≈ 20–50 մվ։
- Արմատում խորը հետազոտվում են լավագույն `minimaxRootK = 60` թեկնածուները, ներքին հանգույցներում՝ լավագույն `opponentTopK = 30`-ը։
- **Թաքնված ինֆորմացիա (հոռետեսական մոտեցում).** խաղացողի քայլը սիմուլացնելիս ենթադրվում է, որ նա կարող է խաղալ իր կապուկի **ցանկացած** քարտ, որի մասին հայտնի չէ, որ այն ձեռքում չէ։ Այսպիսով Minimax-ը պատրաստվում է վատագույն դեպքին։

## 7. «Դժվար» մակարդակ. Monte Carlo Tree Search (`mcts.js`)

MCTS-ը ծառը կառուցում է աստիճանաբար՝ բազմաթիվ պատահական խաղարկումների (սիմուլյացիաների) հիման վրա։ Յուրաքանչյուր իտերացիա ունի 4 փուլ.

1. **Ընտրություն (selection).** արմատից իջնում ենք ծառով՝ ամեն հանգույցում ընտրելով այն զավակին, որի **UCB1** արժեքն առավելագույնն է.

   `UCB1 = w/n + c · √(ln N / n)`

   որտեղ `w/n`-ը զավակի միջին արդյունքն է, `n`-ը՝ նրա այցելությունների թիվը, `N`-ը՝ ծնողինը, `c = 1.41`։ Առաջին գումարելին օգտագործում է արդեն հայտնի լավ քայլերը (exploitation), երկրորդը խրախուսում է քիչ ուսումնասիրված քայլերը (exploration)։ Հակառակորդի հանգույցներում օգտագործվում է `1 − w/n`։
2. **Ընդլայնում (expansion).** ծառին ավելացվում է մեկ նոր հանգույց (դեռ չփորձված լավագույն թեկնածու քայլը)։
3. **Սիմուլյացիա (rollout).** նոր հանգույցից խաղը շարունակվում է `rolloutRounds = 3` ռաունդ, որտեղ երկու կողմն էլ խաղում են «Հեշտ» մակարդակի կանոններով՝ առանց պատահականության։ Վերջնական դիրքը գնահատվում է գնահատման ֆունկցիայով և սիգմոիդով բերվում [0, 1] միջակայք՝ `p = 1 / (1 + e^(−score/10))` (հաղթանակ = 1, պարտություն = 0)։
4. **Հետտարածում (backpropagation).** արդյունքը գումարվում է ճանապարհի բոլոր հանգույցներին։

Ժամանակի ավարտին ընտրվում է **ամենաշատ այցելված** քայլը։

**Դետերմինիզացիա (determinization).** Քանի որ խաղացողի ձեռքը թաքնված է, յուրաքանչյուր իտերացիայի սկզբում պատահականորեն ընտրվում է խաղացողի հնարավոր ձեռքը և կապուկի հերթականությունը (անհայտ քարտերից)։ Հակառակորդի հանգույցներում դիտարկվում են միայն այն քայլերը, որոնք հնարավոր են այդ ձեռքով։ Շատ իտերացիաների արդյունքում AI-ը ստանում է միջինացված գնահատական բոլոր հնարավոր ձեռքերի համար։

**Լրացուցիչ բարելավումներ.**

- **Աստիճանական լայնացում (progressive widening).** հանգույցի զավակների թիվը աճում է այցելությունների հետ (`≤ 2·√n`), որպեսզի փոքր բյուջեի դեպքում ծառը չափից լայն չլինի։ Արմատում դիտարկվում են լավագույն 40 թեկնածուները, ներքին հանգույցներում՝ 10-ը։
- **Նախնական գնահատականներ (priors).** արմատի քայլերը նախ գնահատվում են կարճ Minimax որոնմամբ (խորություն 3), և յուրաքանչյուր զավակ սկսում է 30 «վիրտուալ այցով»՝ այդ գնահատականին համապատասխան։ Սիմուլյացիաները հետո հաստատում կամ հերքում են այս առաջին կարծիքը։
- Ժամանակի բյուջեն՝ `mctsTimeMs = 5000` մվ (կարգավորվում է), 1 վայրկյանում կատարվում է ≈ 15–25 հազար իտերացիա։

## 8. «AI-ը ինչ է մտածում» վահանակը (`explain.js`)

AI-ի յուրաքանչյուր քայլից հետո խաղը ցույց է տալիս.

- մակարդակը և ալգորիթմը, գնահատված վիճակների / իտերացիաների թիվը, որոնման խորությունը, ծախսված ժամանակը,
- լավագույն 3 թեկնածու քայլերը՝ գնահատականով (Minimax) կամ հաղթելու տոկոսով և այցերի թվով (MCTS),
- **ավտոմատ գեներացված բացատրություն**։ Ընտրված քայլի հետևանքով ստացված դիրքը համեմատվում է «ոչինչ չանելու» դիրքի հետ, և գտնվում է ամենաշատ փոխված հատկանիշը, օրինակ՝

  > Ընտրեցի «Աղեղնավոր», քանի որ թշնամու «Վահանակիր» միավորը հաջորդ քայլին չի կարող հասնել «Աղեղնավոր» միավորին, իսկ ամենամեծ ազդեցությունը՝ «Դաշտում զորքի արժեք» +6.0։

  Պատճառը («քանի որ…») ընտրվում է դիրքի պարզ վերլուծությամբ՝ պաշտպանություն աշտարակի մոտ, անհասանելի հեռահար զորք, հմայքի դիպած թշնամիների թիվ և այլն։

### 8.1. v1.2-ի լրացումները (`src/ui/aipanel.js`)

- **Լավագույն 3 թեկնածուները դաշտում.** AI-ի քարտերի բացումից հետո թեկնածու տեղադրումները մի քանի վայրկյան երևում են դաշտում՝ համարակալված կիսաթափանցիկ նշաններով (ընտրվածը՝ ոսկեգույն)։ Մինչև բացումը AI-ի ընտրության մասին ոչինչ չի երևում. մտածելու ընթացքում ցուցադրվում է միայն ցուցիչը և անցած ժամանակը։
- **Հաղթելու հավանականության գծապատկեր.** `chooseMove`-ը վերադարձնում է `stats.winProb`՝ AI-ի սեփական գնահատականը։ «Դժվար»-ի համար դա ընտրված քայլի հաղթանակների մասն է MCTS-ի սիմուլյացիաներում, «Միջին»-ի համար՝ `σ(գնահատական / sigmoidScale)`, «Հեշտ»-ի համար՝ նույն σ-ն ստատիկ գնահատականից։ Գծապատկերը ցույց է տալիս այս արժեքը ռաունդ առ ռաունդ ամբողջ մարտի ընթացքում։
- **«Հեշտ» մակարդակի գործած կանոնը.** յուրաքանչյուր քարտի համար ցուցադրվում է, թե առաջնահերթության որ կանոնն է այն ընտրել (`EASY_RULE_HY`)։
- **«Ինչպե՞ս է աշխատում» պատուհանը.** կարճ բացատրություն երեք SVG գծապատկերով՝ ռաունդի մոդելը, Minimax + Alpha-Beta ծառը և MCTS-ի չորս փուլերը։
- Վահանակը կարելի է ծալել (փոքր էկրաններում լռելյայն ծալված է) կամ ամբողջովին անջատել կարգավորումներում։

## 9. Web Worker

Խաղում AI-ը աշխատում է առանձին հոսքում (`worker.js`). գլխավոր հոսքը ուղարկում է խաղի վիճակը, Worker-ը վերադարձնում է ընտրված քայլը և վիճակագրությունը։ Այդ ընթացքում ինտերֆեյսը մնում է արձագանքող։ Եթե Worker-ը հասանելի չէ, նույն կոդը կանչվում է անմիջապես։

## 10. Փորձարարական արդյունքներ

Աղյուսակները ստեղծվում են `npm run experiments` հրամանով և պահվում `docs/experiments/` պանակում.

1. Մակարդակների համեմատություն (Հեշտ / Միջին / Դժվար)։
2. MCTS-ի ուժը՝ կախված մտածելու ժամանակից։
3. Առաջին քայլի առավելությունը։
4. Քարտերի հավասարակշռությունը։
5. Գնահատման ֆունկցիայի կշիռների համեմատություն։
6. Կանոնների տարբերակներ և ոչ-ոքիների հաճախությունը։
7. Մարտի պահերի քանակը (`battleTicks` = 1, 2, 3, 4)։

Յուրաքանչյուր աղյուսակի կողքին ստեղծվում է նույն անունով `.svg` գծապատկեր։ Հավասարակշռության արագ ստուգման համար կա `node tools/balance.js` գործիքը, իսկ `tools/selfplay.js`-ում՝ `human` մակարդակը («Հեշտ»-ի կանոններ + 40% պատահական քայլ + 1–2 քարտ ռաունդում), որը մոդելավորում է սկսնակ խաղացողին։

Մեկ առանձին շարք կարելի է խաղարկել այսպես՝

```
node tools/selfplay.js --a=hard --b=medium --games=100 --mctsMs=200 --swapSides
```
